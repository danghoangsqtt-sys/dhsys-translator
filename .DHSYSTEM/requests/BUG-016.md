# BUG-016 — Packaged Windows GUI menus omit dynamic window modules

- Type: BUG
- Priority: P0 release blocker
- State: verified locally; clean-runner release gate pending
- Source: dh-audit, user report 2026-10-04
- References: `videotrans/ui/menu_list.py`, `videotrans/ui/_setup_menus.py`, `videotrans/winform/__init__.py`, `sp.spec`, `scripts/smoke_sidebar.py`

## Evidence

The Python 3.12 Windows onedir executable opens, but each of the five dynamic left-sidebar actions fails when selected. An executable probe reported `No module named 'videotrans.winform.fn_recogn'` and the equivalent error for `fn_peiyin`, `fn_fanyisrt`, `fn_peiyinrole`, and `fn_vas`. The same probe opened all five from source. The menu action invokes `get_win(name)`, which imports its window and matching UI class at runtime; the candidate spec included only the smoke-tested `chatgpt` dialog. Existing UI tests checked action creation but did not trigger these routes.

The expanded import inventory covers all 72 dynamic GUI menu entries. Source imports pass 72/72; the package rebuilt with only the five sidebar windows passes 7/72 and fails 65/72, mostly at missing `videotrans.winform.*`. The issue therefore affects translation, TTS, STT, tools and help menus as well as the left sidebar.

## Acceptance

Bundle the declared dynamic window/UI modules, invoke all five sidebar actions, and open all 72 dynamic menu routes from the rebuilt executable outside the install tree. Add both probes to the candidate workflow so these routes cannot regress unnoticed. Retain the release gate until the clean Windows runner and Git persistence checks pass.

## Local verification — 2026-10-04

`sp.spec` now derives the 139 required dynamic module names from the 72 menu declarations. The Python 3.12.13 onedir candidate at `E:\data\2.MyProject\2026\pytransvideo-menus-fixed-de199e560dc343d096ff2a0bc7de3240` passed the packaged sidebar smoke **5/5** and the full menu smoke with `--open` **72/72**. It also passed provider/dialog, CLI, SRT and generated MP4 smoke from that directory, and the GUI remained running after 15 seconds of offscreen startup. The 540-test Python 3.12 suite passed. This verifies menu opening; remote provider tasks and complete user media workflows are still outside this smoke.
