# Task 3.2 — Correct Windows artifact pipeline

Audit requests: BUG-007 (P1), BUG-016 (P0 release blocker). Resume after tasks 3.4–3.9 and runtime validation in 3.1.

## Objective

Make the Windows build workflow use a spec present in Git, produce the artifact path it checks and uploads, include required application resources and FFmpeg, and keep publication behind the release smoke gate.

## Paths

- `.gitignore` — allow the tracked PyInstaller spec.
- `sp.spec` — create an onedir artifact and exclude user model/cache data.
- `.github/workflows/main.yml` — align artifact paths, remove false GUI `--help` smoke, upload candidate artifact without automatic release.
- `docs/runtime-matrix.md`, `docs/review-nemotron-2026-10-04.md` — record Python 3.12 test evidence, corrected defects, and open release gates.
- `.DHSYSTEM/phases/3/tasks/3.2.md`, phase/tracker state — record checks and remaining release risk.

## File-Level Plan

1. Fix spec tracking and convert its output to onedir matching the workflow.
2. Remove model/cache collection; stage sidecar resources needed by the frozen executable's current relative paths.
3. Validate workflow and spec statically, run relevant tests, and leave release publication gated on packaged media smoke.

## Best practices

- Do not package downloaded models, personal output, configuration, or logs.
- Keep build artifact reviewable; do not publish without running the packaged application.
- Pin tool versions to the manifest where possible.

## Verification

- `git check-ignore sp.spec` must fail and Git status must show the spec as untracked/added.
- Workflow paths match `COLLECT` output.
- Inspect artifact contents and invoke at least one dynamically imported provider and dialog from the extracted package.
- Invoke every left-sidebar window and import all dynamically declared GUI menu modules from the executable; source-only QAction tests do not cover this.
- Python 3.10 tests remain green; full Windows runner build and media smoke are still required before release.
