## Objective

Start jobs through the existing path and show per-stage progress, Stop, and the Phase 9 result panel for single and batch jobs.

## Work

- Start calls `win_action.check_start` after applying wizard params; errors from the check return the user to the step that needs fixing.
- Progress list per stage (Nhận dạng, Dịch, Đọc giọng, Ghép) driven by `workflow_state` events; overall bar; Stop uses the existing stop action.
- Single job: embed `ResultPanel` on completion. Batch: list of videos with state; selecting a finished row loads its receipt into the panel.
- "Dịch video khác" resets to Step 1 keeping language/voice/caption choices.

## Implementation Notes

- **Stage events:** task progress percentages only grow in coarse +3 steps, so they cannot tell which stage is running. Each stage method (`prepare`, `recogn`, `trans`, `dubbing`, `align`, `assembling`) emits one `SignMsg(type="stage", text=<key>)` right after its existing skip guards. Both the single-video `only_one.Worker` and the batch `MultVideo` queues call these methods, so both paths report stages; the classic `update_data` ignores the new type. `workflow_state.py` needs no change.
- **Run page** (`step_run.py`): a ready state (file count, purpose, output folder); after start, one row per job with name, current stage (Chuẩn bị → Nhận dạng → Dịch → Lồng tiếng → Ghép video), progress bar from `set_precent`, the latest log line, and done/error state; an overall bar; **Dừng** uses the existing toggle (`check_start` → `update_status('stop')`). It listens to `SignalHub.new_message` and only handles the uuids in `win_action.obj_list`.
- **Start:** the shell's **Bắt đầu dịch** calls `check_start`; if it returns without starting (validation message), the page stays ready. While running, the shell is locked (no Back, stepper or classic switch).
- **Results:** `show_result_dialog` hands receipts to the run page when the wizard owns the job, so the `ResultPanel` (Phase 9) is embedded instead of a popup; history is still recorded. Batches list each video; selecting a finished one loads its receipt (the panel's selector). "Chỉ tạo SRT" jobs have no video receipt, so the page shows the output folder instead. **Dịch video khác** clears the file list and returns to Step 1, keeping language/voice/subtitle choices.
- **Verification without downloads:** the focused tests and a real `MainWindow` probe drive the page with real `SignMsg` sequences. A full media job needs a recognition model download and online translation/TTS, so it runs only with the owner's approval.

## Result

PASS for the UI and routing on 2026-10-23; the real-media acceptance item is **pending owner approval**. **Bước 3** (`step_run.py`) shows a ready summary, then one row per video with the current stage (Chuẩn bị → Nhận dạng giọng nói → Dịch phụ đề → Lồng tiếng → Ghép video & phụ đề), its progress bar and latest log, an overall bar and **Dừng**. Stage names come from a new `SignMsg(type="stage")` emitted by each pipeline stage method, which both the single-video and batch paths call; the classic workspace ignores it. **Bắt đầu dịch** goes through the classic `check_start`; the wizard is locked while running. Finished jobs show the Phase 9 `ResultPanel` inside the page (batch results in its selector) instead of a popup, and history is still recorded. **Dịch video khác** clears the video list and returns to Step 1 with the other choices kept.

A real `MainWindow` probe (only the heavy pipeline start was replaced; messages went through the real `SignalHub` and classic `update_data`) verified stages, progress, batch rows, embedded results and re-entry. It also found and fixed four issues: the classic `_reset()` clears its job list before reporting results, so the page now tracks its own output receipts to claim results; Start stayed visible after a job although the classic queue was cleared, so Start is withheld until the user leaves step 3 or starts another video, and the queue is re-synced from the wizard list; duplicate folder/"translate another" buttons; and a `&` mnemonic in "Sửa phụ đề & xuất lại" / "Lưu & xuất lại". The run page scrolls so results never force the window taller. A separate `reexport_status` line in the result panel stops an asynchronous playback error from hiding re-export messages (this race made a Task 9.2 test flaky).

Not yet verified: a full media job started from the wizard. It needs a faster-whisper model download plus online translation/TTS, so it waits for the owner's go-ahead. Evidence: 15 new focused tests; 830 full Python 3.12 tests pass with the known `pydub/audioop` warning; locale JSON, `compileall`, provider audit and `git diff --check` pass; `params.json` was unchanged by the probes.
