# Task 8.2 — Close provider visibility leaks

## Objective

Every desktop surface that lists providers honours the curated policy: main workspace, quick tools, standalone tool windows, provider profiles and the recommended profile. WebUI and CLI keep full functionality but default their choices and help text to the curated set.

```text
webui.py

```

## Work

- Inventory all provider `QComboBox` and `QAction` surfaces (grep for registry name lists and `register_provider_combo`).
- Register every unregistered combo with `register_provider_combo`.
- Order WebUI provider dropdowns so curated providers come first and others sit under an "Advanced" grouping; keep values unchanged.
- Update CLI help examples to curated providers and Vietnamese voices (replace `zh-CN-YunyangNeural` examples with `vi-VN-HoaiMyNeural`).
- Add a scripted surface audit that fails when a provider combo is created without registration.

## File-Level Plan

- `videotrans/winform/fn_*.py`, `videotrans/component/*.py` — register provider combos created in standalone windows.
- `videotrans/ui/provider_profiles.py` — ensure built-in profiles reference only curated providers.
- `webui.py` — reorder/group dropdown choices; do not change submitted values.
- `cli.py` — update help examples only.
- `scripts/audit_provider_surfaces.py` — static scan used by the test.
- `tests/test_provider_surfaces.py` — run the audit and open each standalone window offscreen to check hidden rows.

## Implementation Notes

Inventory on 2026-10-22: all seven desktop provider combos (`main_win` ×3, `ui/fn_peiyin`, `ui/fn_peiyinrole`, `winform/fn_fanyisrt`, `winform/fn_recogn`; the `winform/fn_peiyin*` windows reuse the `ui/` classes) already call `register_provider_combo`; provider menu actions are filtered by `apply_menu_visibility`; built-in profiles use only curated IDs. No `component/*.py` window lists providers. Remaining surfaces:

- `webui.py` — the three provider dropdowns list every provider in registry order. Use Gradio `(label, value)` choices: curated names first, others after with an "(Advanced)" label; the value stays the registry name so `_*_index_from_display` and saved params are unchanged.
- `cli.py` — `--list providers` marks non-curated rows `[advanced]` (indexes unchanged); help/epilog TTS examples switch from `zh-CN-YunyangNeural` to `vi-VN-HoaiMyNeural`.
- `scripts/audit_provider_surfaces.py` — AST scan: every `addItems(<provider name list>)` receiver must also be passed to `register_provider_combo` in the same module.
- `tests/test_provider_surfaces.py` — runs the audit on the repo, proves it flags an unregistered combo, and checks WebUI ordering/value round-trip and CLI listing.

## Best Practices

- Presentation only: never filter what the backend accepts.
- Keep offscreen Qt tests (`QT_QPA_PLATFORM=offscreen`) deterministic.

## Result

PASS on 2026-10-22. Desktop combos were already registered (inventory above), so no window needed changes. WebUI provider dropdowns now list curated providers first and the rest with an "(Advanced)" label while keeping registry names as values; a probe confirmed Gradio 6.8 accepts a saved Advanced value (DeepSeek) and preprocesses it unchanged. `cli.py --list providers` marks non-curated rows `[advanced]` with unchanged indexes, and CLI help uses `vi-VN-HoaiMyNeural`. `scripts/audit_provider_surfaces.py` reports 0 problems and is enforced by `tests/test_provider_surfaces.py`.

Deviation: instead of opening each standalone window offscreen, the guard is a static AST audit of every `addItems(<provider list>)` call; the windows' runtime visibility is covered by the existing combo-registration tests and will be re-checked in the Task 8.3 frozen probe.

Evidence: 133 focused provider/WebUI/CLI tests and 748 full Python 3.12 tests pass with the known `pydub/audioop` warning; `compileall` and `git diff --check` pass.
