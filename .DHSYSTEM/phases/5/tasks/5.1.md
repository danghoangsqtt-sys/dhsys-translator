# Task 5.1 — Readiness model and Windows probes

State: PASS

## Objective

Create a side-effect-free system readiness service that reports factual machine capabilities and workload-specific readiness without scanning personal files or changing the machine.

## Paths

- `videotrans/diagnostics/__init__.py`
- `videotrans/diagnostics/system_readiness.py`
- `tests/test_system_readiness.py`
- `docs/runtime-matrix.md`
- `.DHSYSTEM/phases/5/PHASE-STATE.md`
- `.DHSYSTEM/TRACKER.md`
- `.DHSYSTEM/HANDOFF.json`

## File-Level Plan

- `videotrans/diagnostics/system_readiness.py`: define serializable probe/result types, severity/action codes, workload profiles and bounded injectable probes for Windows/architecture, CPU, RAM, free disk, GPU/VRAM, NVIDIA/CUDA visibility, bundled FFmpeg/ffprobe and writable user-data/cache locations.
- `tests/test_system_readiness.py`: simulate capable, CPU-only, low-resource, missing-resource, command-timeout and unknown-hardware machines without requiring a real GPU/network/admin rights.
- `docs/runtime-matrix.md`: document measured thresholds and distinguish required runtime from optional acceleration/provider/model requirements.
- State files: record exact focused/full test evidence; keep the phase in progress until frozen acceptance.

## Best Practices

- Prefer standard library plus existing `psutil`; do not add WMI dependencies unless evidence shows they are necessary.
- Pass subprocess arguments as lists, never `shell=True`; set short timeouts and treat failures as unknown/optional where appropriate.
- Return stable codes for UI/tests and translate only at the presentation boundary.
- Do not enumerate user files, environment secrets, registry credentials or provider configuration values.

## Acceptance

1. Probe output distinguishes required, recommended, optional and unknown findings by workload.
2. CPU-only systems are not rejected merely because CUDA is unavailable.
3. Missing bundled FFmpeg/resources are blockers; optional GPU/local-model gaps are not mislabeled as blockers for basic mode.
4. Exportable data contains no API keys, media names, full private paths or arbitrary environment values.
5. Focused tests, relevant runtime/frozen-path tests, full Python 3.12 suite and `git diff --check` pass.
