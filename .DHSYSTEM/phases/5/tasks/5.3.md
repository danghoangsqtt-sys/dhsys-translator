# Task 5.3 — Consent-based remediation assistant

State: in_progress

## Objective

Offer safe, explicit actions for verified missing prerequisites while preventing silent installs, command injection and inappropriate GPU/driver automation.

## File-Level Plan

- Define a fixed remediation registry containing only verified publisher/source, exact package ID or official URL, privilege/restart metadata and post-check.
- Support WinGet only when present and only with exact IDs; otherwise offer official manual links/instructions.
- Show a confirmation dialog with action details before every install/open-link/download operation and allow clean cancellation.
- Keep GPU driver/CUDA/cuDNN as guidance, and route model installation through existing verified model-download mechanisms rather than a generic package shell.
- Add redacted structured logs and post-action re-scan.

## Best Practices

- No `shell=True`, free-form network commands, auto-accepted unknown agreements or `--ignore-security-hash`.
- Do not elevate the main app permanently. Let the selected installer/Windows UAC request elevation only when required.
- Verify exit code plus post-condition; a zero exit alone is not success.
- Never install Python/Qt/FFmpeg globally for a packaged recipient build.

## Acceptance

1. Every remediation requires user confirmation and can be cancelled without state change.
2. Only allowlisted exact actions execute; hostile labels/paths/arguments cannot become commands.
3. Missing WinGet, offline network, denied UAC, reboot-required and installer failure have readable recovery paths.
4. GPU drivers/CUDA and large models are never silently installed.
5. Focused security/state/UI tests and full Python 3.12 suite pass.
