## File-Level Plan

- Automate local install/upgrade/uninstall and portable extraction against isolated user data; never target real user output directories.
- Verify startup twice, Việt/Anh readiness UI, all existing routes, hard/soft subtitle media contracts and one representative Vietnamese-target provider flow where network/provider availability permits.
- Confirm the test environment has no source Python requirement and that program files can be read-only while user data/output remain writable.
- Record compact non-sensitive evidence: artifact hashes/sizes, OS/architecture, test counts, probe results and known optional skips.
- Finalize the recipient guide covering install, portable use, first-run check, CPU/GPU choices, model/provider setup, support-report export, upgrade, uninstall and data backup.

## Best Practices

- Prefer Windows Sandbox, a disposable VM or an isolated Windows user/profile; never claim clean-machine evidence from the developer's configured source environment alone.
- Keep provider/network failures truthful and preserve non-destructive fallback guidance.
- Do not commit generated installers, ZIPs, media, models, credentials or unsanitized reports.

## Acceptance

1. A recipient-style environment launches portable and installed builds without Python/Qt/FFmpeg setup.
2. System Check identifies actual CPU/GPU/resource conditions and suggested actions without false PASS claims.
3. Install, upgrade and uninstall behave predictably; user data survives by default.
4. Hard/soft subtitles, Vietnamese-target output, provider fallback and frozen UI smoke pass with exact evidence.
5. Local artifact hashes and recipient instructions are complete. GitHub is not required; the current manifest/version changes only after this gate passes.
