# Task 9.3 — Frozen playback acceptance

## Objective

Prove that the packaged Windows build plays the outputs it produces (H.264/AAC MP4 with hard subtitles, and MP4 with a `mov_text` soft track) inside the result panel.

## Paths

```text
sp.spec
scripts/smoke_frozen_ui.py
.DHSYSTEM/phases/9/evidence/
```

## Work

- Confirm `sp.spec` collects the Qt Multimedia FFmpeg backend plugin and its DLLs; add them if missing.
- Extend `scripts/smoke_frozen_ui.py` (every run, like the Phase 8 provider check) with a result-panel check: generate a short hard-subtitle MP4 and a `mov_text` soft MP4 with the bundled FFmpeg, play each in `ResultPanel` offscreen for ~2 s, and assert `MediaStatus` reaches Loaded/Buffered and the position advances.

## Implementation Notes

- Phase 8 build already contains `PySide6/plugins/multimedia/ffmpegmediaplugin.dll` and the `avcodec/avformat/avutil/swresample/swscale` DLLs via the PyInstaller PySide6 hooks; `sp.spec` only needs a change if the rebuilt candidate lacks them.
- The probe also checks Task 9.2 in the packaged interpreter: Original/Side-by-side switching on a real file, the soft-subtitle caption strip, and a real `run_reexport` (soft → new `-2` file) using the bundled FFmpeg on `PATH` (set by `configure/_paths.py`).
- Rebuild `dist/sp` from this branch, stage resources as in Task 8.3, and run core/sidebar/menus plus UI `vi` and `en_US` (`PYVIDEOTRANS_LANG` per run). Evidence goes to `.DHSYSTEM/phases/9/evidence/` with machine paths redacted.

## Verification

```powershell
Start-Process dist\sp\sp.exe -ArgumentList scripts\smoke_frozen_ui.py,<report.json>,vi -Wait   # with PYVIDEOTRANS_LANG=vi, then en_US
```

## Acceptance

- Evidence JSON records the candidate SHA-256, media status sequence and position delta for hard and soft outputs, in Vietnamese and English UI.
