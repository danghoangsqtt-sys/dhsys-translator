# Task 9.2 — Compare modes, re-export and history

## Objective

Let users compare translated and original video, see soft subtitles while previewing, fix subtitles and re-export without re-running recognition/translation/TTS, and reopen recent results.

## Work

- Segmented control Bản dịch / Gốc / Cạnh nhau; side-by-side uses two players sharing one position and muting the original.
- SRT overlay for soft-subtitle outputs, driven by `positionChanged` and a parsed cue list.
- "Sửa phụ đề & xuất lại": open the existing subtitle editor on the target SRT, then re-run only assembly into `_unused_video_path(...)` so the previous output is kept.
- `result_history.py`: append receipts (paths, timestamp, languages) to a JSON list in the user data dir, cap 20, drop entries whose files no longer exist when displayed.

## File-Level Plan

- `videotrans/ui/result_panel.py` — modes, overlay, re-export button.
- `videotrans/ui/result_history.py` — pure load/append/prune functions with atomic write.
- `videotrans/task/_stage_assemble.py` — expose an assemble-only entry that reuses cached `novoice.mp4` and dubbed audio when present; fail with a clear message if the cache was cleared.
- `videotrans/mainwin/_actions_task.py` — record history on completion.
- Tests — cue lookup, history cap/prune, re-export path selection.

## Implementation Notes (revised 2026-10-22)

Findings: the task cache (`novoice.mp4`, `will_embed.m4a`) is deleted by `set_end` after every successful job, and both existing subtitle editors (`component/onlyone_set_recogn*.py`) are bound to a running job (`app_cfg.onlyone_*`, `parent.screen_size`). So:

- **Re-export** does not reuse the cache. `videotrans/task/reexport.py` rebuilds the output from files that persist: the original input video, the dubbed `<target>.m4a` in the output folder (or the original audio when nothing was dubbed) and the edited target SRT. Subtitles are prepared by the existing `SubtitleMixin._process_subtitles` (same wrapping, bilingual join and ASS styling) in a managed temp folder, then FFmpeg encodes with libx264 at the configured CRF/preset into `_unused_video_path(...)`, so the previous output is never overwritten. Re-export is disabled with an explanation when the job used video slow-down (`video_autorate`), because the original video timing no longer matches the dubbed audio. It runs in a `QThread` so the UI stays responsive.
- **Subtitle editing** uses a small result-only dialog (`ui/result_subtitle_editor.py`): a table of time ranges with editable text only (timings stay aligned with the dubbed audio), focusable/selectable/editable, unsaved-change prompt, no auto-close — the Task 4.13 behaviours. It saves the target SRT before re-export.
- **Receipt** gains optional `source_video`, `source_sub`, `target_sub`, `source_language_code`, `target_language_code`, `target_language`, `output_srt` and `video_autorate` so the panel can compare and re-export; older receipts simply hide those actions.
- **Compare modes:** Bản dịch (output), Gốc (input, same position), Cạnh nhau (output with sound plus the muted original following play/pause/seek within 300 ms).
- **Soft subtitles:** a caption strip under the video shows the current cue(s) from the SRT while playing soft-subtitle outputs (a widget overlay on `QVideoWidget` is not reliably painted on Windows).
- **History:** `ui/result_history.py` keeps up to 20 receipts (paths and language codes only) in `<user data>/videotrans/result_history.json`, written atomically; a corrupt file is reset with a log warning; entries whose video no longer exists are dropped when listed. The result window gets a "Gần đây" selector fed from history.

## Result

PASS on 2026-10-22. The result window now has **Bản dịch / Gốc / Cạnh nhau** modes (switching keeps the playback position; side-by-side shows the muted original following the translated video), a caption strip for soft-subtitle outputs, a selector that lists the current results followed by up to 20 recent ones from `result_history.json`, and **Sửa phụ đề & xuất lại**, which opens a text-only editor and re-exports on a worker thread into a new `-N` file next to the previous output.

Deviations from the original File-Level Plan, both recorded in the revised Implementation Notes: (1) re-export rebuilds from the original video, the dubbed `.m4a` and the edited SRT instead of reusing the task cache, because `set_end` deletes the cache after success, and it is disabled when the job used video slow-down; (2) editing uses a result-only text editor instead of the job-bound `onlyone_set_recogn*` dialogs.

Evidence: a real FFmpeg re-export produced hard (295 changed pixels in the bottom third at 1 s), soft (`mov_text`, `vie`) and bilingual-soft outputs without touching the previous file or leaving temp folders; a source-run probe switched modes during playback (952 ms → original continued to 1532 ms; side-by-side drift 31–55 ms). A stale `LoadedMedia` status emitted before the new source loads was found by that probe, fixed and covered by a regression test. `videotrans/result_history.json` is gitignored user data. 785 full Python 3.12 tests pass (24 new) with the known `pydub/audioop` warning; locale JSON, `compileall`, provider audit and `git diff --check` pass. Frozen playback remains Task 9.3.
