# Task 4.14 — Make subtitle output explicit and verifiable

Status: `in_progress`

## Objective

Make every subtitle-output choice describe the result the viewer will actually get. Fresh tasks in the main translated-video workflow start with always-visible hard subtitles, while existing persisted enum values keep their current meanings. No-subtitle output requires an explicit choice and confirmation, and completed jobs report the selected mode and output paths.

## Compatibility boundary

- Preserve the persisted `subtitle_type` enum values and both bilingual source/target orders.
- Apply the new hard-subtitle default only to fresh main-workflow state; do not migrate an existing saved choice silently.
- Keep soft subtitles and no subtitles available as deliberate choices.
- Do not modify visible SRT content to influence TTS and do not change provider/model IDs or Chinese media-language support.

## Verification plan

1. UI/state regression proves fresh main-workflow state selects the existing hard-subtitle enum, persisted values round-trip unchanged, mode transitions never select no-subtitle implicitly, and bilingual ordering remains stable.
2. UI regression proves Vietnamese/English labels describe visible hard subtitles, player-controlled soft subtitles and no-subtitle output; no-subtitle export requires a clear confirmation.
3. Output-receipt regression proves mode, video/SRT paths and the soft-track player instruction are shown after completion.
4. A real FFmpeg hard-subtitle fixture is decoded and compared with an unsubtitled baseline to prove visible subtitle pixels.
5. A real FFmpeg soft-subtitle fixture is inspected with `ffprobe` to prove the expected subtitle stream and language metadata.

## Execution notes

- 2026-10-05: task entered `in_progress`; repository preflight and the required Phase 4 contracts were reviewed before application edits.

## Scope

- Reframe `subtitle_type` choices in Vietnamese/English around user-visible results, not implementation terms.
- Default the main “Tạo video dịch” flow to hard subtitles. Keep soft subtitle and no-subtitle as deliberate alternatives.
- Display an output receipt that states subtitle mode, output paths and what the chosen player must do.
- Add a warning before a video is produced with no subtitles.

## Acceptance

1. A fresh main-workflow task defaults to hard subtitles without changing the legacy persisted enum mapping.
2. A hard-subtitle fixture visibly contains subtitles in decoded frames.
3. A soft-subtitle fixture contains exactly the expected subtitle stream and language metadata, verified with `ffprobe`.
4. `No subtitles` is never selected silently by mode transitions.
5. Existing bilingual modes keep their source/target ordering.
