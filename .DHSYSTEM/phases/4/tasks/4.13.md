# Task 4.13 — Make subtitle correction operable and readable

## Scope

- Repair the two recognition-result subtitle dialogs so editable cells receive focus and visible selection.
- Replace the local dark table stylesheet with palette-compatible, high-contrast rules.
- Remove automatic countdown/automatic save as the default behavior. Show explicit `Save and continue`, `Continue without saving`, and `Cancel` actions plus a dirty-state indicator.
- Support double-click, Enter/F2 and keyboard traversal; label non-editable timing/line cells clearly.

## Expected touchpoints

`videotrans/component/onlyone_set_recogn.py`, `videotrans/component/onlyone_set_recogn2.py`, `videotrans/component/_danspmixin.py`, `videotrans/styles/light.qss`, focused Qt tests.

## Acceptance

1. A user can select and edit subtitle text and start/end time using mouse and keyboard.
2. Text and headers meet normal light-theme contrast; selected/editing state is unmistakable.
3. Dialog never saves or closes merely because time elapsed unless the user explicitly enables an auto-continue option.
4. Save writes the expected SRT; continue-without-saving leaves it byte-for-byte unchanged.
5. Regression covers both first-pass and second-pass editor dialogs.
