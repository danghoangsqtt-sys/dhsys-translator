# Task 4.2 — Separate workflow view state from task widgets

## Objective

Expose a small, presentation-only workflow state (`idle`, `running`, `error`, `complete`) in the five existing workflow cards. The state must be derived from the existing action status and `SignMsg` messages, while queue management, media processing, output paths, saved settings, dialogs, and CLI behavior remain unchanged.

## Paths

- `videotrans/ui/workflow_state.py` — create a dependency-free mapper and presenter for task event type → view state.
- `videotrans/ui/en.py` — add one localized workflow-status label and a method that applies the view state to the existing cards.
- `videotrans/mainwin/main_win.py` — construct the presenter after the generated UI exists.
- `videotrans/mainwin/_actions_task.py` — forward the existing application status and received `SignMsg` events to the presenter without changing existing handling branches.
- `videotrans/styles/light.qss` — render the status label and card borders for each view state in the approved light palette.
- `videotrans/language/en_US.json` — add labels for the workflow states.
- `videotrans/language/vi_VN.json` — add Vietnamese labels for the workflow states.
- `videotrans/language/zh_CN.json` — add Chinese labels for the workflow states.
- `tests/test_workflow_state.py` — test the mapper and presenter independently of PySide6 workers.
- `tests/test_ui_en_split.py` — prove the generated UI can apply a view state without replacing original controls.
- `tests/test_light_workspace.py` — prove the visual-state selectors remain in the shared stylesheet.
- `scripts/smoke_frozen_ui.py` — verify the packaged generated UI applies a running state.

## File-Level Plan

1. Keep the mapper pure Python: action states and `SignMsg.type` map to view states; unknown event types retain the prior visual state.
2. Place the status label beside the existing instructions and set a Qt dynamic property on the existing five section frames. No widgets receive business logic.
3. Create the presenter only after `setupUi`, then notify it from the current `update_status` and `update_data` paths. The original action code runs unchanged.
4. Add localized labels and state-specific QSS borders using white, gray and `#14452F` as the base visual system.
5. Test mapping, generated UI, stylesheet selectors and frozen UI. Run the complete Python 3.12 suite before rebuilding the Windows candidate.

## Best practices

- Do not parse worker log text to claim a specific processing stage.
- Do not put media, filesystem, queue or worker behavior in `videotrans/ui/workflow_state.py`.
- Retain existing object names, parent widgets, actions and signal connections.
- Keep new user-visible text localized.
- Use a dynamic Qt property and polish the widget after changing it so state styles are deterministic.
