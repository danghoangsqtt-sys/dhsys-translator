# Task 4.17 — Controlled provider reduction and migration

State: PASS

## Objective

Introduce an explicit provider/data-plane policy before any provider is hidden or removed. Preserve every persisted numeric provider/model ID and exact saved selection, prove that the Local profile is truly local-only only when its configurable endpoint is loopback, and disclose when audio/text leaves the device. This task may recommend Gemini/OpenRouter paths, but it must not claim unlimited free quota or silently replace a user's saved provider.

No provider is deleted, renumbered or removed from Advanced/Custom during this task. China-hosted cloud APIs and locally executed China-origin open models are classified separately; Chinese media-language support remains unchanged.

   - Keep the existing Local/Gemini/Custom profile keys and their numeric provider IDs unchanged.
   - Add deterministic endpoint classification for loopback/local-network/public/unknown without DNS or network I/O.
   - Add a profile-policy result that states whether media/text leaves the device, whether a profile is currently local-only, and what fallback/readiness note applies.
   - Treat `Local LLM` as local-only only for loopback endpoints (`127.0.0.0/8`, `localhost`, `::1`); an empty or public endpoint must never be reported as proven local-only.
   - Keep Custom conservative because its data plane depends on the exact selected providers/endpoints.
2. `workspace_shell.py`
   - Show policy text next to the existing profile hint.

3. Tests

   - Cover loopback IPv4/IPv6/localhost, empty endpoint and public/remote URL classification.
   - Prove failed Local readiness leaves the prior profile and provider indexes untouched.
   - Assert Chinese media-language codes/models remain available and are not tied to provider visibility policy.
   - Keep policy/state tests separate from any real provider/media tests.
4. Docs/state
   - Record that no provider was removed in 4.17 unless migration/privacy/local-only gates prove it safe.
   - Document Gemini/OpenRouter as remote services with current quota/rate-limit behavior, never as unlimited free infrastructure.
   - Preserve independent Phase 3 clean-runner/full-media/release gates.

## Compatibility / Privacy Boundaries

- Persisted fields `recogn_type`, `translate_type`, `tts_type`, `provider_profile` and `provider_profile_custom` keep their existing meanings.
- `translator.ID_NAME_DICT`, `recognition.ID_NAME_DICT` and `tts.ID_NAME_DICT` numeric IDs are frozen for this task.
- Provider credentials/endpoints are neither deleted nor logged by the policy layer.
- Built-in local models are distinguished from remote APIs even when the model/provider project originated in China.
- China-hosted cloud APIs are remote/off-device; their existence does not justify removing local Chinese-capable models or `zh-cn`, `zh-tw`, `yue` media support.
- OpenRouter and Gemini are remote/off-device and subject to provider-side quotas/rate limits. Fallback messaging must be informative and non-destructive.

## Acceptance

1. No provider is deleted until every persisted ID/configuration has an explicit migration or compatibility behavior.
2. UI reduction/policy does not remove Chinese media-language support.
3. Local profile is reported/accepted as local-only only with a loopback Local LLM endpoint and its deterministic contract can be exercised with public network unavailable.
4. Documentation and UI identify whether a profile transmits media/text off-device.
5. A rejected Local-profile readiness check does not change the prior profile or provider indexes.
6. Gemini/OpenRouter guidance includes quota/rate-limit and local/custom fallback text without claiming an unlimited free SLA.
